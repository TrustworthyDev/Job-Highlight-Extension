      What gets shared

      Chrome keeps every profile's extension storage separate, so by default each profile has its own history. Turning sync on puts these in one file that all profiles read and write:

      • Clicked jobs — so a job you opened in one profile shows as viewed in the others.
      • Hidden jobs — hide a card once, it stays hidden everywhere.
      • Blocked companies — one block list.
      • Keyword groups — the same highlights on every profile.

      The on/off toggles in the popup stay per-profile, so one profile can run with highlighting off without changing the others.

      Turning it on

      1. Install Node.js if you don't have it — the helper that owns the file is a small Node script. Check with node --version in a terminal.
      2. Copy the setup command with the button below. It already contains this profile's extension ID, which Chrome requires the helper to be registered against.
      3. Open a terminal in the extension's native-host folder and paste the command. It writes a small manifest into the Windows registry telling Chrome where the helper lives.
      4. Restart Chrome completely — every window, including background ones. Chrome only reads the registration at startup.
      5. Reopen this page. The badge at the top of this section should read On. If it still reads Off, see below.
      6. Repeat on each other profile. Load the extension there, then run the setup command from that profile's page — the ID differs per profile, and each one needs its own registration. The file itself is shared, so nothing is duplicated.

      How it stays in step

      A profile reads the file when a page opens, and each click or hide sends only that one change, which the helper merges into the file. Profiles never overwrite each other — two profiles editing different keyword groups both keep their edit. An open tab also re-reads the file every minute and whenever you switch back to its window, so it picks up other profiles' changes without a reload. Designed for use one profile at a time.

      If it still says Off

      • Node isn't installed or isn't on PATH — node --version must work in a plain terminal.
      • The command was run in the wrong folder — it has to be the native-host folder inside this extension.
      • Chrome wasn't fully restarted — closing the last window isn't always enough; quit from the tray if it's still running.
      • The extension ID changed — reloading an unpacked extension from a different folder gives it a new ID. Copy the command again and re-run it.

      Nothing breaks while it's off: the extension just keeps everything in this profile's own storage, and switching sync on later picks up from there.

      Backup

      Save your toggles and keyword groups to a file, or restore them.

      With sync on, every keyword change is also written straight to linkedin-job-tools-settings.json in the extension folder, in the same format as the export below — so there is always a readable, up-to-date copy you can open or commit. That copy is one-way: editing the file by hand does not change anything in Chrome, use Import settings for that. Without the native host installed, nothing can be written to disk, so use Export settings instead.
